## The bug (diagnosed, root cause CONFIRMED)

Packaged Plus install on the dev/test box showed **"Operational System Error → Failed to
load dashboard data"** ([src/app/page.tsx:634-649](src/app/page.tsx)). Cause: **the installer
was built without the bundled PostgreSQL binaries**, so no database ever starts and every
DB query 500s.

Evidence (gathered live on the install):
- `C:\Program Files\WhiteVanOps\resources\pgsql\bin\pg_ctl.exe` does NOT exist.
- `%APPDATA%\whitevanops` has only the license files — no `pgdata`, `postgres.log`, or
  `bootstrap-complete` sentinel. The DB lifecycle never ran.
- Nothing listening on 5433; port 3000 is `WhiteVanOps.exe` self-booting its own server.
- `pgsql/` does not exist in the repo working copy — and electron-builder **silently skips
  missing extraResources sources**, so a `pgsql`-less build machine shipped a DB-less installer.
- Failure chain: self-boot server → `ensurePostgres()` found no `pg_ctl.exe` → (old code)
  logged "skipping" and returned `{managed:false}` → `pg.Pool` targets 127.0.0.1:5433 where
  nothing runs → dashboard shell renders on the still-valid JWT (middleware never hits the DB)
  → `/api/dashboard` is the first real DB call → 500 → error screen.
- Masked on the office PM2 machine: `isServerUp()` is true there, so `startServer()` returns
  before `ensurePostgres` ever runs.

## ✅ DONE 2026-07-12 (commit `a3aeada` on `claude/handoff-corrections-61e69c`)

**C. Hardening — a DB-less installer can no longer ship or start silently:**
1. [scripts/electron-build.js](scripts/electron-build.js) now **hard-fails** (was: warning)
   when `pgsql/bin/pg_ctl.exe` is missing before packaging, and after packaging asserts that
   `dist-electron/win-unpacked/resources/pgsql/bin/pg_ctl.exe` **and**
   `resources/nextjs/node_modules/next` exist.
2. [electron/postgres.js](electron/postgres.js) **throws** "Database engine missing: …" when
   the URL is localhost + the port is free + no bundled binaries, so
   [electron/main.js](electron/main.js) shows a clear startup-error dialog instead of booting
   a broken server. Verified by driving `ensurePostgres()` against a fake resources dir —
   throws as expected. PM2-reuse path unaffected (returns earlier via `isServerUp()`).

**Latent 2026-07-10 fixes — were never committed to any branch, now re-applied:**
3. [electron/main.js](electron/main.js): packaged builds call
   `app.setPath('userData', %APPDATA%\whitevanops\profile)` before ready — no more shared
   dev/packaged Chromium profile (cause of the earlier "not valid JSON" stale-SW bug).
4. [public/sw.js](public/sw.js): navigations are now **network-first** (cache is offline
   fallback only); cache name bumped `wvo-field-v1` → `wvo-field-v2` so old caches purge.

**Docs updated:** CLAUDE.md (Electron section) + MANUAL_Setup_Installation.md §1.

- **New bug found & fixed during the rebuild (commit `870e1ed`):** the backup route's
  `process.cwd()` pg_dump lookup made Next.js trace **the whole project** into

  Fixed with `outputFileTracingExcludes` in [next.config.ts](next.config.ts)

  [scripts/electron-build.js](scripts/electron-build.js).

  no pgAdmin 4, correct `WVO_DEFAULT_TIER`):
  - `dist-electron/WhiteVanOps-Base-Setup.exe` — 273 MB (Jul 12 15:37)
  - `dist-electron/WhiteVanOps-Plus-Setup.exe` — 273 MB (Jul 12 15:46)
  These are the first installers that contain ALL of today's fixes (bundled DB, guards,
  dedicated Chromium profile, network-first SW, normal size).
